## Changes
- **Douyin downloads work again** (#70). Since August Douyin's gateway answers 403 to a request without an `x-tt-argus` header, so f2 0.0.1.7 (the version 0.7.16 shipped) failed on every post and the only way in was "Add video file". Motio now pins the f2 commit that sends that header (and a `uifid` from the guest cookie): full links, links with tracking, a pasted Share sentence and older posts download again, a photo post still says it is photos. The lock file gains `httpx-socks` and `ruamel-yaml` and loses nine packages. Details, the review of the 35 f2 files that load and the new risk are in `docs/DOUYIN_F2.md`.
- **AI pictures are counted in Stats and the monthly budget** (#69). Every new fal picture (scene pictures and character portraits) is recorded at its price; Stats totals, the per-channel cost, the budget (it pauses auto-make and stops AI clips at 100 %) and the project header include it. A cached picture and the free placeholder record nothing. The Stats hint now says Claude tokens, pictures and clips are counted (it used to say Claude "isn't counted").
- **A project waiting for approval no longer shows "Done"** (#68). Opening a project by link from another project's page could keep the first project's last progress event, hiding the Approve bar until a reload.

## Before you use it
- **A remote engine has to be updated for the Douyin fix** (the Hetzner server and the Windows PC): the in-app update replaces only the engine inside the app. The other two changes work with an older engine, except that the picture costs are only recorded by an updated one.
- **f2 is pinned to an unreleased upstream commit.** Douyin only checks that `x-tt-argus` is present; if it starts checking the value the 403 returns and f2 needs another bump. The fallback chain (f2, then yt-dlp with cookies, then "Add video file") stays. f2 now also reads optional `~/.f2/conf.yaml`, a `conf.yaml` in the engine's working directory and `F2_CONFIG`; do not put one there.
- **Claude API key:** a key that is not scoped to a workspace is refused by the Anthropic API ("must include the anthropic-workspace-id header") and Motio cannot send that header. Create the key inside a workspace in the Claude Console.
- **ElevenLabs:** a restricted key needs the Voices → Read permission, or a voice ID saved in Settings; otherwise every video fails at the voice step with a raw 401.

## Verification
- Automated tests on the release commit (Linux-run on a Mac, Python 3.12): **647 passed** with FFmpeg on PATH; `ruff check motio tests` clean; `pnpm build` succeeds. CI runs the same on Ubuntu and Windows plus `cargo clippy`.
- Before this release, 0.7.16 was installed on the Mac and used with real keys: three videos from the Douyin hot list and an AI video with fal pictures were made end to end (82 to 84 s each, quality check passed), gates, re-render and script edit worked. That QA report found the three changes above.
- The Douyin fix was checked live through `search.download` and in a frozen engine built from the branch on macOS (Tools → Download saved the video).
- **Not tried:** the Windows build and the Hetzner server on this version, a `v.douyin.com` short link and a removed post on the new f2, the in-app update from 0.7.16 to 0.7.17, and the app in a real Tauri window (the screens were exercised in a browser against the engine).
- **Known limits, left for a later release:** an "Anthropic workspace ID" setting; a clear message when the ElevenLabs voice list is forbidden; the "Monthly voice budget" label in Settings still says voice although the budget counts Claude, pictures and clips; a failed refresh error crowds the Trending title.
